## 评测说明

- 生成日期：2026-11-24；运行方式：离线多轮放置仿真。
- Seed：`42`；每个场景、每个变体均为 `200` 轮，所有变体复用对应场景的同一到达序列。
- 负载标定：原始 CPU 档位 `{100,200,500,1000}m` 的期望为 450m；各档位统一乘以 `目标 × 集群CPU / (轮数 × 分布期望)` 后取整。本次期望总需求目标为集群 CPU 的 83%，不是另设固定档位。
- 集群：6 个 Ready 且无 taint 的节点；n1~n4 为 4000m/8Gi，n5~n6 为 8000m/16Gi，总容量 32000m/64Gi。
- 租户权重为 4/2/1/1；`balanced` 按权重到达，`hot-tenant` 中权重 4 的租户占 70% 到达，其余按 2:1:1 分配。为制造局部热点，最后 5% 轮次的热点 Pod 需求乘 18，采样期望按 `0.7×(0.95+0.05×18)+0.3` 修正后再做总量标定。
- 不包含真实 kubelet 指标：`Usage` 固定为 0、`UsageKnown=true`、`MetricsKnown=true`，排除指标缺失对对比的干扰。
- 延迟仅统计进程内 `Place` 调用耗时，以 µs 展示并保留 1 位小数；平均决策耗时 = 全部调用总耗时 / 轮数，P99 使用 nearest-rank 分位数。不包含 API、数据库、网络或 kubelet 开销；Windows 计时精度可能使 P99 显示为 0.0。
- 不可行率 = 未放置轮次 / 总轮次；未放置包括 `Place` 返回错误，以及当前调度核用于表达容量不足的 `NO_CANDIDATE`。

## 指标口径

- **Jain**：先求租户主导份额 `max(已分配 CPU / 集群 CPU, 已分配内存 / 集群内存)`，再除以租户权重，对所得四个值计算 Jain 指数。
- **CPU / 内存利用率**：集群已分配 request / 集群总 allocatable。
- **碎片率**：仿真结束后，对残余容量放不下基准 Pod（100m/128Mi）的节点，累加 `min(残余 CPU / 集群 CPU, 残余内存 / 集群内存)`；其余节点计 0。
- **平均租户 HHI**：每租户计算 `Σ_node(该租户在该节点的副本数 / 该租户总副本数)²`，再对四个租户取均值；越低越散布，无副本租户计 0。
- **最大节点副本占比**：先求每租户在单个节点上的最大副本占比，再取四个租户中的最大值；越低表示单租户越少集中于一台节点。
